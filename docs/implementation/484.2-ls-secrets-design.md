# Workspace Secrets Design - DX Consistency

**Issue**: #489 (Phase 2 of #484)
**Date**: 2025-12-01
**Status**: Draft

## Executive Summary

This document defines SDK and CLI interfaces for workspace secrets management, ensuring consistency with Langstar patterns while incorporating security requirements from Phase 1.5.

**Key Decision**: Secrets use POST-based upsert pattern (not traditional CRUD) for security and simplicity.

## 1. SDK Design

### 1.1 Type Definitions

Based on Phase 1 research and playground-settings precedent:

```rust
// sdk/src/secrets.rs

use serde::{Deserialize, Serialize};

/// A workspace secret key (response from list endpoint).
///
/// Security: Values are NEVER returned by the API.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SecretKey {
    /// The secret key name (e.g., "ANTHROPIC_API_KEY")
    pub key: String,
}

/// Request to create or update workspace secrets.
///
/// Used for both create AND update operations (upsert pattern).
/// Set `value` to `None` to delete a secret.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SecretUpsert {
    /// The secret key name
    pub key: String,

    /// The secret value, or None to delete
    #[serde(skip_serializing_if = "Option::is_none")]
    pub value: Option<String>,
}

impl SecretUpsert {
    /// Create a new secret upsert request to set a value
    pub fn set(key: impl Into<String>, value: impl Into<String>) -> Self {
        Self {
            key: key.into(),
            value: Some(value.into()),
        }
    }

    /// Create a new secret upsert request to delete a secret
    pub fn delete(key: impl Into<String>) -> Self {
        Self {
            key: key.into(),
            value: None,
        }
    }
}
```

**Design Decisions**:
- No `Secret` type (API never returns values)
- `SecretUpsert` for both create/update (matches API pattern)
- `Option<String>` for value (supports delete via null)
- Convenience methods: `set()` and `delete()`
- No UUID ID (secrets identified by key name)

**Precedent**: `sdk/src/playground_settings.rs:81-225`

### 1.2 Client Methods

```rust
// sdk/src/client.rs

impl LangchainClient {
    /// List all workspace secret keys.
    ///
    /// Security: Returns ONLY keys, never values.
    ///
    /// # Example
    ///
    /// ```no_run
    /// # use langstar_sdk::{AuthConfig, LangchainClient};
    /// # async fn example() -> langstar_sdk::Result<()> {
    /// let auth = AuthConfig::from_env()?;
    /// let client = LangchainClient::new(auth)?;
    ///
    /// let keys = client.list_workspace_secrets().await?;
    /// for key in keys {
    ///     println!("Secret: {}", key.key);
    /// }
    /// # Ok(())
    /// # }
    /// ```
    pub async fn list_workspace_secrets(&self) -> Result<Vec<crate::secrets::SecretKey>> {
        let request = self.langsmith_get("/api/v1/workspaces/current/secrets")?;
        self.execute(request).await
    }

    /// Create or update workspace secrets (upsert operation).
    ///
    /// # Permissions
    ///
    /// Requires API key with `workspaces:manage` permission.
    ///
    /// # Example
    ///
    /// ```no_run
    /// # use langstar_sdk::{AuthConfig, LangchainClient};
    /// # use langstar_sdk::secrets::SecretUpsert;
    /// # async fn example() -> langstar_sdk::Result<()> {
    /// let auth = AuthConfig::from_env()?;
    /// let client = LangchainClient::new(auth)?;
    ///
    /// let secrets = vec![
    ///     SecretUpsert::set("ANTHROPIC_API_KEY", "sk-ant-..."),
    ///     SecretUpsert::set("OPENAI_API_KEY", "sk-..."),
    /// ];
    /// client.upsert_workspace_secrets(secrets).await?;
    /// # Ok(())
    /// # }
    /// ```
    pub async fn upsert_workspace_secrets(
        &self,
        secrets: Vec<crate::secrets::SecretUpsert>,
    ) -> Result<()> {
        let request_builder = self
            .langsmith_post("/api/v1/workspaces/current/secrets")?
            .json(&secrets);
        self.execute_status_only_request(request_builder).await
    }

    /// Delete a workspace secret.
    ///
    /// Convenience method that calls `upsert_workspace_secrets` with null value.
    ///
    /// # Example
    ///
    /// ```no_run
    /// # use langstar_sdk::{AuthConfig, LangchainClient};
    /// # async fn example() -> langstar_sdk::Result<()> {
    /// let auth = AuthConfig::from_env()?;
    /// let client = LangchainClient::new(auth)?;
    ///
    /// client.delete_workspace_secret("OLD_API_KEY").await?;
    /// # Ok(())
    /// # }
    /// ```
    pub async fn delete_workspace_secret(&self, key: impl Into<String>) -> Result<()> {
        let secrets = vec![crate::secrets::SecretUpsert::delete(key)];
        self.upsert_workspace_secrets(secrets).await
    }
}
```

**Design Decisions**:
- `list_workspace_secrets()` - explicit workspace scoping
- `upsert_workspace_secrets()` - reflects true API behavior (accepts `Vec` for batch)
- `delete_workspace_secret()` - singular convenience wrapper
- Returns `()` for write operations (no response body from API)
- Explicit security notes in docs

**Precedent**: `sdk/src/client.rs` dataset methods, playground-settings methods

### 1.3 Error Handling

Reuse existing `LangstarError` enum - no new variants needed:

| Scenario | Error Type | Status Code |
|----------|-----------|-------------|
| Missing permissions | `ApiError` | 403 |
| Invalid key name | `ApiError` | 400 |
| Network failure | `HttpError` | - |

**Example**:
```rust
match client.upsert_workspace_secrets(secrets).await {
    Ok(()) => println!("Secrets updated"),
    Err(LangstarError::ApiError { status: 403, .. }) => {
        eprintln!("Error: Missing workspaces:manage permission");
    }
    Err(e) => eprintln!("Error: {}", e),
}
```

**Precedent**: `sdk/src/error.rs`, existing error handling patterns

## 2. CLI Design

### 2.1 Command Structure

**Command name**: `langstar secrets` (plural, matches common CLI conventions)

```rust
/// Commands for managing LangSmith workspace secrets
#[derive(Debug, Subcommand)]
pub enum SecretsCommands {
    /// List all workspace secret keys
    List,

    /// Set (create or update) a workspace secret
    Set {
        /// Secret key name
        key: String,

        /// Read secret value from file
        #[arg(long, value_name = "FILE", conflicts_with_all = ["interactive", "from_env"])]
        from_file: Option<PathBuf>,

        /// Prompt interactively for secret value (hidden input)
        #[arg(long, conflicts_with_all = ["from_file", "from_env"])]
        interactive: bool,

        /// Read secret value from environment variable
        #[arg(long, value_name = "VAR", conflicts_with_all = ["from_file", "interactive"])]
        from_env: Option<String>,
    },

    /// Delete a workspace secret
    Delete {
        /// Secret key name to delete
        key: String,

        /// Skip confirmation prompt
        #[arg(short = 'y', long)]
        yes: bool,
    },
}
```

**Design Decisions**:
- Three commands: `list`, `set`, `delete` (no `get` - API doesn't support it)
- `set` for both create/update (matches upsert pattern)
- Multiple secure input methods (Phase 1.5 requirement)
- Conflicts between input methods (only one at a time)
- `--yes` flag for delete confirmation

**Precedent**: `cli/src/commands/prompt.rs`, model-providers design

### 2.2 Secure Input Methods (Phase 1.5 Requirement)

**CRITICAL**: Secret values must NEVER appear in command arguments, output, or logs.

#### Method 1: File Input (Recommended for Automation)

```bash
# Create file with secret value (secure: does not expose secret in command line or history)
cat > /tmp/secret.txt <<'EOF'
(paste secret here)
EOF

# Set secret from file
langstar secrets set ANTHROPIC_API_KEY --from-file /tmp/secret.txt

# Clean up
rm /tmp/secret.txt
```

**Implementation**:
```rust
if let Some(file_path) = from_file {
    let value = fs::read_to_string(&file_path)
        .map_err(|e| CliError::Other(anyhow!(
            "Failed to read secret file: {}", e
        )))?
        .trim()
        .to_string();

    // Validate non-empty
    if value.is_empty() {
        return Err(CliError::Other(anyhow!("Secret file is empty")));
    }

    return set_secret(client, key, value).await;
}
```

#### Method 2: Interactive Prompt (Recommended for Manual Use)

```bash
# Prompt with hidden input
langstar secrets set ANTHROPIC_API_KEY --interactive
# Prompts: Enter secret value: ********
```

**Implementation**:
```rust
use rpassword::prompt_password;

if interactive {
    let value = prompt_password("Enter secret value: ")
        .map_err(|e| CliError::Other(anyhow!(
            "Failed to read password: {}", e
        )))?;

    if value.is_empty() {
        return Err(CliError::Other(anyhow!("Secret value cannot be empty")));
    }

    return set_secret(client, key, value).await;
}
```

**Dependency**: `rpassword = "7.3"` (used by cargo, git)

#### Method 3: Environment Variable

```bash
# Set secret from env var (safer: do not echo secret in shell history)
read -s MY_SECRET; export MY_SECRET
# or from a password manager:
# export MY_SECRET="$(pass show anthropic/api-key)"
langstar secrets set ANTHROPIC_API_KEY --from-env MY_SECRET
```

**Implementation**:
```rust
if let Some(env_var) = from_env {
    let value = env::var(&env_var)
        .map_err(|_| CliError::Other(anyhow!(
            "Environment variable {} not found", env_var
        )))?;

    if value.is_empty() {
        return Err(CliError::Other(anyhow!(
            "Environment variable {} is empty", env_var
        )));
    }

    return set_secret(client, key, value).await;
}
```

#### Method 4: Stdin (Pipe)

```bash
# Pipe from file
cat /tmp/secret.txt | langstar secrets set ANTHROPIC_API_KEY

# Pipe from command
echo "sk-ant-..." | langstar secrets set ANTHROPIC_API_KEY

# Pipe from password manager
pass show anthropic/api-key | langstar secrets set ANTHROPIC_API_KEY
```

**Implementation**:
```rust
// If no input method specified, read from stdin
use std::io::{self, Read};

let mut value = String::new();
io::stdin()
    .read_to_string(&mut value)
    .map_err(|e| CliError::Other(anyhow!(
        "Failed to read from stdin: {}", e
    )))?;

let value = value.trim().to_string();
if value.is_empty() {
    return Err(CliError::Other(anyhow!("No secret value provided")));
}

set_secret(client, key, value).await
```

**Security validation**: All methods validate non-empty values before sending to API.

**Precedent**: Similar to `gh secret set` (GitHub CLI)

### 2.3 Output Sanitization (Phase 1.5 Requirement)

**CRITICAL**: Secret values must NEVER appear in command output.

#### List Command Output

```bash
# Table format (default)
$ langstar secrets list
╭────────────────────────────╮
│ Secret Key                 │
├────────────────────────────┤
│ ANTHROPIC_API_KEY          │
│ OPENAI_API_KEY             │
│ DATABASE_URL               │
╰────────────────────────────╯

Found 3 secrets

# JSON format
$ langstar secrets list -f json
[
  {"key": "ANTHROPIC_API_KEY"},
  {"key": "OPENAI_API_KEY"},
  {"key": "DATABASE_URL"}
]
```

**Implementation**:
```rust
#[derive(Debug, Tabled)]
struct SecretKeyRow {
    #[tabled(rename = "Secret Key")]
    key: String,
}
```

#### Set Command Output

```bash
$ langstar secrets set ANTHROPIC_API_KEY --from-file key.txt
✓ Secret 'ANTHROPIC_API_KEY' updated successfully

# ❌ NEVER OUTPUT:
# ✓ Secret 'ANTHROPIC_API_KEY' set to: sk-ant-...
```

**Implementation**:
```rust
formatter.success(&format!("Secret '{}' updated successfully", key));
// NEVER: formatter.success(&format!("Secret '{}' set to: {}", key, value));
```

#### Delete Command Output

```bash
$ langstar secrets delete OLD_KEY
Are you sure you want to delete secret 'OLD_KEY'? [y/N]: y
✓ Secret 'OLD_KEY' deleted successfully

$ langstar secrets delete OLD_KEY --yes
✓ Secret 'OLD_KEY' deleted successfully
```

#### Error Messages

**IMPORTANT**: Errors must not leak secret values.

```rust
// ✅ GOOD: No secret value
return Err(CliError::Other(anyhow!("Secret file is empty")));

// ❌ BAD: Leaks secret
return Err(CliError::Other(anyhow!("Invalid secret value: {}", value)));
```

**Precedent**: GitHub CLI `gh secret`, Kubernetes `kubectl create secret`

### 2.4 Command Examples

#### Basic Usage

```bash
# List all secrets
langstar secrets list

# Set secret interactively
langstar secrets set API_KEY --interactive

# Set secret from file
langstar secrets set API_KEY --from-file ~/.secrets/key.txt

# Set secret from env var
export MY_KEY="..."
langstar secrets set API_KEY --from-env MY_KEY

# Set secret from stdin
cat key.txt | langstar secrets set API_KEY

# Delete secret (with confirmation)
langstar secrets delete OLD_KEY

# Delete secret (skip confirmation)
langstar secrets delete OLD_KEY --yes
```

#### CI/CD Usage

```bash
# In GitHub Actions
- name: Set LangSmith secret
  run: |
    echo "${{ secrets.ANTHROPIC_KEY }}" | \
      langstar secrets set ANTHROPIC_API_KEY
  env:
    LANGSMITH_API_KEY: ${{ secrets.LANGSMITH_API_KEY }}

# In script
#!/bin/bash
for key_file in secrets/*.txt; do
  key_name=$(basename "$key_file" .txt)
  langstar secrets set "$key_name" --from-file "$key_file"
done
```

## 3. Comparison with Other Resources

| Aspect | Datasets (Standard CRUD) | Secrets (Upsert Pattern) |
|--------|-------------------------|-------------------------|
| **Create** | `POST /datasets` → Dataset | `POST /secrets` → void |
| **List** | `GET /datasets` → Dataset[] | `GET /secrets` → SecretKey[] |
| **Get by ID** | `GET /datasets/{id}` → Dataset | ❌ Not supported |
| **Update** | `PATCH /datasets/{id}` → Dataset | `POST /secrets` (upsert) |
| **Delete** | `DELETE /datasets/{id}` → void | `POST /secrets` (value: null) |
| **Response** | Full object with data | Keys only (no values) |
| **Permissions** | Standard API key | `workspaces:manage` required |

**Key Differences**:
- No GET by key (security)
- POST serves as create/update
- No DELETE endpoint (use POST with null)
- List returns keys only
- Elevated permissions required

## 4. Security Threat Model (Phase 1.5)

### 4.1 Attack Vectors & Mitigations

| Attack Vector | Risk | Mitigation |
|---------------|------|------------|
| **Shell history** | Secrets in args persist in `~/.bash_history` | No secrets in CLI arguments |
| **Process list** | `ps aux` shows full command lines | No secrets in CLI arguments |
| **LLM output** | Agents read stdout/stderr | Never echo secret values |
| **Log files** | CI logs capture command output | Sanitize all output |
| **Error messages** | Validation errors might echo input | Redact secrets in errors |

### 4.2 Security Guarantees

✅ **Guaranteed Safe**:
- Command arguments (no secret values)
- Command output (only key names, success messages)
- Error messages (no secret values)
- Logs (no secret values leaked)

✅ **Secure Input Methods**:
- File input (ephemeral files, user-managed)
- Interactive prompt (hidden input via `rpassword`)
- Environment variables (process-local)
- Stdin (pipe, no shell history)

❌ **Explicitly Forbidden**:
- `--value` flag for direct secret input
- Echoing secret values in any output
- Storing secrets in shell history
- Exposing secrets in error messages

### 4.3 Claude Code Skill Guidelines

When wrapping `langstar secrets` in Claude Code skills:

**DO**:
- Use file-based input: `langstar secrets set KEY --from-file /tmp/secret`
- Read list output (only key names)
- Use `--yes` flag for automation: `langstar secrets delete KEY --yes`

**DON'T**:
- Never log secret values
- Never pass secrets as CLI arguments
- Never parse or display secret values
- Never store secrets in skill code

**Example skill wrapper**:
```bash
# ✅ GOOD: File-based input
echo "$SECRET_VALUE" > /tmp/secret
langstar secrets set "$KEY_NAME" --from-file /tmp/secret
rm /tmp/secret

# ❌ BAD: Secret in arguments
langstar secrets set "$KEY_NAME" --value "$SECRET_VALUE"  # FORBIDDEN
```
